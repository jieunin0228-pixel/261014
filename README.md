# ECS 룰 변환기

생명보험 약관 텍스트를 읽어 보험금 심사 시스템(ECS)의 룰 테이블 행으로 변환하는 정적 웹앱입니다. 모든 데이터는 더미이며, 외부 API나 서버 없이 브라우저 안에서만 처리합니다.

## 실행 방법

`index.html`을 브라우저로 열면 바로 동작합니다. 엑셀 라이브러리(SheetJS)는 `vendor/`에 포함되어 있어 인터넷 연결이 필요하지 않습니다.

1. [샘플 약관]을 누르거나, 약관을 붙여넣거나, .txt 파일을 엽니다(UTF-8과 EUC-KR 모두 읽습니다).
2. [변환]을 누르면 오른쪽에 룰 테이블이 표시됩니다. 행을 클릭하면 아래쪽에 약관 원문 발췌와 주의·테스트 항목이 나옵니다.
3. [정답지와 비교]로 정답지 엑셀(`samples/answer_key.xlsx` 형식)을 올리면 일치·불일치 결과가 표시됩니다.
4. [엑셀 다운로드]를 누르면 룰테이블·심사자수기·근거없음 시트를 받을 수 있고, 비교를 실행한 뒤라면 정답지비교 시트도 함께 받습니다.

## 개발·검증

```bash
npm install
npm run build:samples   # samples/dummy_terms.txt, samples/answer_key.xlsx 재생성
npm test                # 단계별 단위 테스트(16건)
NODE_PATH=$(npm root -g) node scripts/ui-check.js /tmp   # Playwright 화면 점검(선택)
```

## 파일 구성

| 경로 | 역할 |
|---|---|
| `src/schema.js` | ECS 컬럼, 정답지 컬럼, 사고유형·사인그룹·계약상태 코드, 등록 변수 마스터(모두 더미) |
| `src/engine.js` | 조항 분리 → 사망 급부 추출 → 금액·갱신·면책·소멸 조항 추출 → 룰 행 생성 → 위험 표시 → 정답지 비교 |
| `src/app.js`, `index.html` | 화면 |
| `samples/dummy-terms.js` | 더미 약관 원문(단일 원본) |
| `scripts/answer-key-data.js` | 사람이 직접 작성한 정답지 행(엔진 출력에서 파생하지 않음) |

## 입력 형식 전제

엔진은 생명보험 표준약관의 문언 패턴을 기준으로 한 규칙 기반 추출기이며, 약관을 자유롭게 이해하는 모델이 아닙니다. 다음 형식을 전제로 합니다.

- 조문은 `제N조(제목)`, 항은 `①②…`, 호는 `1.`, 목은 `가.` 형식이어야 합니다.
- 사망 급부는 제목에 "지급사유"가 들어간 조문의 호에서 `…사망하였을 경우: ○○보험금` 형식으로 읽습니다.
- 지급금액은 `가입금액의 N%`로, 감액은 `다만, … 계약일부터 N년 이내 … 가입금액의 N%`로 읽습니다.
- 면책은 제목에 "지급하지 않는 사유"가 들어간 조문에서 읽고, 사유는 `src/schema.js`의 사인그룹 키워드와 매칭합니다.

이 형식과 다른 문언은 행으로 만들어지지 않거나 "근거 없음"으로 분류되므로, 실제 약관에 적용하려면 패턴과 사인그룹 마스터를 확장해야 합니다.

## 변환 규칙 구현 내용

| 규칙 | 구현 |
|---|---|
| 1. 사고유형별 행 | 지급사유 문언의 원인 범위로 사고유형을 정합니다. 원인을 정하지 않은 "사망"은 일반·일반재해·교통재해, "재해로"는 일반재해·교통재해, "교통재해로"는 교통재해 행이 됩니다. |
| 2. 경과기간 감액 | 감액 단서는 `경과기간<=N년`(감액)과 `경과기간>N년`(정상) 두 행으로 나눕니다. 단서가 "재해 이외의 원인"으로 한정되면 일반 사고유형에만 적용합니다. |
| 3. 면책 | 사인그룹과 매칭되는 면책 사유는 `[가입금액] * 0` 행으로 만듭니다. "N년이 지난 후 … 재해 이외의 원인으로 사망한 경우에 해당하는 보험금" 예외는 기간 경계로 면책/지급 행을 나눕니다. |
| 4. 갱신형 | 갱신 조문이 있으면 최초·갱신 행을 나눕니다. 갱신 산식 조항이 명시한 급부에만 `Math.max([가입금액], [기납입보험료])`를 쓰고, 명시하지 않은 급부는 지급금액 조항 문언대로 두면서 ⚠를 표시합니다. |
| 5. 심사자 수기 | 사인그룹 마스터에 없는 사유(심신상실, 수익자·계약자 고의, 실종선고)는 룰 행 없이 [심사자 수기] 탭으로 보냅니다. |
| 6. 근거 조항 | 모든 행에 지급사유·지급금액·면책·소멸 조항과 원문 발췌를 붙입니다. 지급금액 조항을 찾지 못한 급부는 행을 만들지 않고 [근거 없음] 탭으로 보냅니다. |
| 7. ⚠ 표시 | 경계일 포함 여부, 면책기간 기산점, 갱신계약의 기산점 재설정, 갱신 산식 적용 범위, 면책 시 환급 여부, 소멸 조항의 급부 범위처럼 문언으로 확정할 수 없는 사항에 사유를 적습니다. |
| 8. 🔴/🟡 | 경계일 조건, Math.max 산식, 등록되지 않은 변수(`기납입보험료`, `보장개시경과기간`)는 🔴로, 동일 사고유형·사인그룹·조건에 급부가 둘 이상 매핑된 행은 🟡로 표시하고 테스트 시나리오를 적습니다. |

## 설계상 판단

- **구분 색상**: 사망보험금을 지급하는 행은 모두 계약이 소멸하므로, 소멸을 행 구분으로 쓰면 거의 모든 행이 파랑이 됩니다. 그래서 행 배경은 산식 결과(정상 초록, 감액 노랑, 면책 빨강)로 칠하고, 소멸(파랑)은 계약상태처리 열의 배지로 표시합니다.
- **정답지 매칭 키**: 구보장급부명, 사고유형, 사인그룹코드, 계산식결정조건 4개를 키로 짝을 짓고, 상세계산식과 계약상태처리를 비교합니다. 공백 차이는 무시합니다.
- **샘플 정답지의 의도된 차이**: 비교 기능을 시연하려고 2곳을 일부러 다르게 작성했습니다. 교통재해사망보험금의 갱신계약 산식(약관에 없는 Math.max 적용)과 사망보험금 × T20(전쟁) 행 2개입니다. 그래서 샘플 비교 결과는 일치 19, 불일치 1, 정답지에만 2입니다. 두 곳 모두 엔진이 ⚠로 확인을 요청한 지점입니다.

## 보안 참고

`xlsx` 0.18.5(npm 최종 배포판)에는 악의적으로 조작된 엑셀 파일을 읽을 때의 취약점 공지가 있습니다. 정답지 업로드에는 직접 만든 신뢰할 수 있는 파일만 사용해야 하며, 실데이터 환경으로 옮길 때에는 SheetJS 공식 배포처의 최신 버전으로 교체해야 합니다.
