# 약관 담보 분석기

보험 약관 PDF를 올리면 담보를 사망·장해·진단·입원·치료·기타로 분류하여 트리로 보여 주는 PC용 웹앱입니다. 신약관 출시 때 ECS "약관분석 데이터 관리" 화면에 자동산출 룰을 입력하는 담당자가 참고하는 용도입니다. 이 앱은 ECS와 연동하지 않으며, 담당자가 앱 화면을 보면서 ECS에 옮겨 입력합니다.

## 진행 현황

| 단계 | 내용 | 상태 |
|---|---|---|
| 1단계 | PDF 업로드, 목차 기반 담보 분류 트리, 담보 이동·이름 수정 | 완료 |
| 2단계 | 담보별 요약(A·B 영역), 근거 목록(C 영역), ECS 룰 입력 초안(D 영역), 임시 코드마스터, 검토 상태 저장 | 완료 |
| 3단계 | 근거 페이지 PDF 뷰어 연결, 엑셀·JSON 내보내기 | 예정 |
| 4단계 | 구약관 PDF 대비 비교 | 예정 |

## 설치 없이 써 보기 (claude.ai 아티팩트판)

설치 없이 브라우저에서 바로 쓸 수 있는 판을 claude.ai 아티팩트로 게시했습니다. 처음 열면 시험용 가상 약관(246쪽)이 자동으로 분석되어 화면 동작을 바로 확인할 수 있습니다.

아티팩트판은 올린 PDF를 어디로도 보내지 않고 그 브라우저 안에서만 읽습니다. 분석 결과와 수정 내용도 그 브라우저의 저장소에만 남기 때문에 다른 PC나 다른 사람의 화면에서는 보이지 않습니다. 브라우저의 사이트 데이터를 지우거나 시크릿 창에서 열면 저장 내용이 사라집니다. 이런 이유로 아티팩트판은 체험과 확인 용도로 쓰고, 실제 업무에는 아래의 로컬 실행판을 쓰는 것을 권합니다. 2단계의 담보 요약·ECS 초안은 API 키를 서버에만 두어야 하므로 로컬 실행판에서만 제공합니다.

아티팩트 페이지는 `node scripts/build-artifact.js`로 `build/artifact.html`을 만들어 게시합니다. 화면과 분석 로직은 로컬 실행판과 같은 파일을 쓰며, 서버와 통신하는 부분(`public/api-server.js`)만 브라우저 안에서 분석하는 부분(`artifact/api-local.js`)으로 바꿉니다. 함께 게시하는 파일은 `sample_policy.pdf` 하나입니다.

## 설치와 실행

### 처음 한 번: Node.js 설치

[nodejs.org](https://nodejs.org)에서 **LTS** 버전(20.12 이상)을 내려받아 설치합니다. 설치 화면에서는 기본값 그대로 [다음]을 누르면 됩니다.

### 실행

**Windows**에서는 이 폴더의 `시작.bat`을 더블클릭합니다. 처음 실행할 때에는 필요한 구성요소를 자동으로 설치하므로 몇 분 걸릴 수 있습니다. 실행되면 브라우저에 앱 화면이 열립니다.

**명령어로 실행**하려면 이 폴더에서 다음 두 줄을 입력합니다. 두 번째 실행부터는 `npm start`만 입력하면 됩니다.

```bash
npm install
npm start
```

실행 후 브라우저에서 `http://localhost:3000`을 엽니다. 앱을 끝내려면 실행 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

### API 키 설정 (담보 요약·ECS 초안에 필요)

1단계(담보 분류 트리)는 API 키 없이 동작합니다. 2단계부터 담보 요약에 Claude API를 쓰므로, 다음과 같이 키를 설정합니다.

1. 이 폴더의 `.env.example` 파일을 복사하여 이름을 `.env`로 바꿉니다.
2. `.env` 파일을 메모장으로 열고 `ANTHROPIC_API_KEY=` 뒤에 키를 붙여 넣고 저장합니다.

API 키는 이 PC의 서버 프로그램만 읽으며 브라우저 화면으로는 보내지 않습니다. `.env` 파일은 git에 올라가지 않도록 제외되어 있습니다. 키를 넣은 뒤에는 앱을 껐다가 다시 실행해야 적용됩니다.

분석에는 Claude Opus 5.5(`claude-opus-5-5`)를 쓰며, 정확성이 중요한 작업이므로 추론 수준을 `high`로 둡니다. 다른 모델이나 수준을 쓰려면 `.env`에 `CLAUDE_MODEL=`, `CLAUDE_EFFORT=`를 적습니다. 담보 1건 분석마다 API를 한 번 호출하며, 같은 약관의 담보를 이어서 분석하면 약관 원문 부분은 캐시되어 비용이 줄어듭니다. 이미 분석한 담보는 [다시 분석]을 누르기 전까지 다시 호출하지 않습니다. Claude가 안전 사유로 답을 거절하면 API가 자동으로 대체 모델로 다시 시도하도록 설정해 두었습니다(`fallbacks: "default"`).

## 사용 순서

1. [약관 PDF 올리기]를 눌러 약관 PDF를 선택합니다. 진행 막대에 업로드, 쪽별 글자 추출(예: "123 / 400쪽"), 구간 분리, 담보 분류 단계가 표시됩니다. 246쪽 샘플 기준으로 몇 초가 걸립니다.
2. 분석이 끝나면 왼쪽에 담보 트리가 나타납니다. 트리는 대분류(사망·장해·진단·입원·치료·기타 고정) › 중분류(담보를 정의한 약관 이름) › 담보 순서로 구성됩니다.
3. 담보마다 분류 근거 한 줄과 근거 조문, PDF 쪽번호, 약관 인쇄 쪽번호가 함께 표시됩니다. PDF 쪽번호와 인쇄 쪽번호는 표지·목차 때문에 서로 다를 수 있으므로 둘 다 표시합니다.
4. 체크박스로 담보를 여러 개 선택합니다. 대분류나 중분류를 체크하면 그 아래 담보가 모두 선택되고, 일부만 선택되면 상위 체크박스가 부분 선택(−) 상태로 바뀝니다.
5. 선택한 담보마다 오른쪽에 결과 카드가 만들어집니다. 1단계에서는 분류 근거, 정의 약관, 근거 조문과 원문만 표시하며, A·B·D 영역은 2단계에서, C 영역의 PDF 뷰어 연결은 3단계에서 채워집니다.
6. 자동 분류가 틀렸으면 담보 옆 [편집]을 눌러 이름을 고치거나 대분류·중분류를 바꿉니다. 담보가 아닌 항목이 잡혔으면 "목록에서 제외"를 체크합니다. 제외한 담보는 트리 아래 "목록에서 제외한 담보"에서 복원할 수 있습니다. 자동 추출이 놓친 담보는 [담보 직접 추가]로 넣습니다.
7. 수정 내용과 선택 상태는 바로 이 PC에 저장됩니다. 상단의 [최근 분석한 약관 열기]로 이전에 올린 약관을 다시 열 수 있습니다.

### 화면에 나타나는 안내

**OCR 필요**는 PDF 일부 또는 전체가 스캔 이미지여서 글자를 읽지 못한 경우에 표시됩니다. 해당 쪽번호를 함께 보여 주며, 그 쪽의 내용은 분석에서 빠집니다. 이 경우 스캐너 프로그램이나 Adobe Acrobat의 "텍스트 인식(OCR)" 기능을 거친 PDF를 다시 올려야 합니다.

**확인 필요**는 목차를 찾지 못했거나, 목차에는 있는데 본문에서 찾지 못한 약관이 있거나, 제목을 읽지 못한 구간이 있을 때 표시됩니다. 목차에만 있는 약관은 담보가 트리에서 빠졌을 수 있으므로 [담보 직접 추가]로 보완해야 합니다.

## 2단계: 담보 요약과 ECS 룰 입력 초안

1. 트리에서 담보를 선택하고 오른쪽 위의 [선택 담보 분석]을 누릅니다. 카드마다 [분석]·[다시 분석] 버튼도 있습니다. 진행 중에는 카드에 "분석 대기·분석 중"이 표시되고 [중지]로 멈출 수 있습니다.
2. 분석이 끝나면 카드에 네 영역이 채워집니다.
   - **A. 보장 세부조건**은 담보명, 지급사유, 지급금액과 산식, 지급횟수와 한도, 보장개시일, 면책기간, 감액기간과 감액비율, 보험기간과 갱신 여부, 지급하지 않는 사유, 요건의 세부 정의, 지급 후 계약 처리를 항목마다 근거와 함께 보여 줍니다.
   - **B. 전산화 시 주의사항**은 별표 참조, 산출에 영향을 주는 용어 정의, "다만" 단서와 예외, 다른 담보와의 중복지급·택일, 지급률 차이, 기준일 판단을 보여 줍니다. 해석이 갈리는 곳에는 "해석 확인 필요"와 가능한 해석이 붙습니다.
   - **C. 근거 페이지**는 카드에 쓰인 모든 근거를 쪽 순서로 모아 조·항·호, PDF 쪽번호, 인쇄 쪽번호, 원문 인용을 보여 줍니다. 쪽번호를 눌러 PDF로 이동하는 기능은 3단계에서 붙입니다.
   - **D. ECS 룰 입력 초안**은 ECS "약관분석 데이터 관리" 화면과 같은 순서의 필드 44개를 "수정 전 / 수정 후" 칸으로 보여 줍니다. 경과기간별 지급률처럼 조건이 갈리면 행을 나누고 나눈 근거를 적습니다. "수정 후" 칸은 직접 고칠 수 있으며, 고친 코드는 코드마스터와 다시 대조합니다.
3. 상품코드·상품명·판매개시일자는 ECS에서도 수정할 수 없는 항목이므로 앱이 추정하지 않습니다. 카드 위의 "상품 정보"에 직접 입력하면 모든 행에 반영됩니다.
4. 항목마다 "검토완료"를 체크하면 이 PC에 저장되고 카드 위에 "검토 n/전체"로 표시됩니다. 다시 분석해도 검토 기록과 직접 고친 값은 지워지지 않습니다.

### 정확성 장치

Claude가 낸 값은 그대로 쓰지 않고 프로그램이 다음과 같이 다시 확인합니다.

| 확인 | 처리 |
|---|---|
| 항목마다 단 원문 인용이 해당 PDF 쪽에 실제로 있는지 | 그대로 있으면 인정합니다. 같은 약관의 다른 쪽에 있으면 쪽번호를 고치고 "쪽번호 보정"을 붙입니다. 문장 조각이 70% 이상만 맞으면 "원문 일부 일치"를 붙입니다. 찾지 못한 인용은 버립니다. |
| 확인된 근거가 하나도 없는 값 | A·D 영역에서는 값을 숨기고 "근거 미확인"으로 표시합니다. B 영역에서는 항목을 빼고 뺀 건수만 알립니다. |
| 약관에서 찾지 못한 항목 | "약관에 명시 없음"으로 표시하고 추정해서 채우지 않습니다. |
| 코드가 코드마스터에 있는지 | 없는 코드는 비우고 명칭만 남긴 뒤 "코드 확인 필요"로 표시합니다. 임시 코드마스터의 코드를 쓴 칸에는 "임시 코드"가 붙습니다. |
| 별표 안의 수치 | Claude에게 별표의 수치를 보내지 않고 표 이름과 쪽만 알려 주어, 지급률을 풀어 쓰지 못하게 합니다. |

이 확인은 근거가 원문에 실제로 있는지와 코드가 코드마스터에 있는지를 보장합니다. 그러나 해석이 옳은지까지 보장하지는 않으므로, ECS에 입력하기 전에 검토완료 표시로 사람이 확인해야 합니다.

### 코드마스터

실제 코드마스터를 받기 전까지는 앱이 만든 **임시 코드마스터**를 씁니다. 화면의 "코드마스터" 칸에 "임시 코드마스터 사용 중"이 표시됩니다.

- 임시 코드마스터 파일은 `codemaster/임시_코드마스터.xlsx`이며, 화면의 [지금 코드마스터 엑셀로 받기]로도 받을 수 있습니다.
- 출처가 "화면캡처"인 코드(S01 사망, G01 일반, B12 일반재해, B03 교통재해, T00~T03 사인그룹, 9 소멸 등)는 이전에 받은 ECS 화면 캡처에서 확인한 값입니다. 실제 코드일 가능성이 높지만 확인이 필요합니다.
- 출처가 "임시생성"이고 `TMP-`로 시작하는 코드는 앱이 지어낸 값이므로 실제 코드로 바꿔야 합니다.
- 실제 코드마스터로 바꾸려면 이 엑셀의 시트별 코드·명칭을 실제 값으로 고치고 [코드마스터 올리기]로 올립니다. 시트 이름(청구사유, 사고유형, 구보장급부, 사고자유형, 사인그룹, 위험급부, 급부결정조건, 계산식결정조건, 금액유형, 상세계산식, 계약상태처리, 납면처리, 갱신가능불가, 장래연금구분, 보험투자요소)과 1행 머리글(코드, 명칭, 설명)은 그대로 두어야 합니다.
- 코드마스터를 바꾸면 이미 분석한 담보도 새 코드마스터 기준으로 코드를 다시 검사합니다. 새 코드마스터에 맞춰 코드를 다시 제안받으려면 [다시 분석]을 누릅니다.

ECS 화면의 필드 순서나 이름이 앱과 다르면 `server/ecs/fields.js` 한 곳만 고치면 D 영역과 내보내기에 함께 반영됩니다.

### 문제 해결

**"API 키가 설정되지 않았습니다"**가 뜨면 `.env` 파일 이름(확장자 `.txt`가 붙지 않았는지)과 키 값을 확인한 뒤 앱을 다시 실행합니다.

**"Claude API에 연결하지 못했습니다"**가 뜨면 사내 프록시를 거쳐야 하는 경우일 수 있습니다. `시작.bat`은 PC에 `HTTPS_PROXY` 환경변수가 있으면 자동으로 프록시를 쓰게 합니다. 명령어로 실행할 때에는 `NODE_USE_ENV_PROXY=1`과 `HTTPS_PROXY=http://프록시주소:포트`를 함께 설정한 뒤 `npm start`를 실행합니다.

## 데이터 저장과 보안

올린 PDF와 분석 결과는 모두 이 폴더의 `data` 폴더에만 저장되며, 외부 서버나 DB에는 올리지 않습니다. 앱 서버는 이 PC 안에서만(`127.0.0.1`) 접속할 수 있으므로 같은 사내망의 다른 PC에서는 접속할 수 없습니다.

| 위치 | 내용 |
|---|---|
| `data/files/` | 올린 원본 PDF입니다. 파일 내용의 해시값을 파일명으로 씁니다. |
| `data/cache/` | 분석 결과입니다. 같은 PDF를 다시 올리면 파일명이 달라도 분석을 반복하지 않고 이 결과를 엽니다. |
| `data/cache/<해시>/analysis/` | 담보별 Claude 분석 결과와 원문 대조 결과입니다. |
| `data/reviews/` | 담보 이름 수정, 분류 이동, 제외, 직접 추가, 선택 상태, 검토완료 표시, "수정 후" 직접 수정 값, 상품 정보입니다. 분석을 다시 해도 지워지지 않습니다. |
| `data/codemaster/` | 올린 코드마스터입니다. 없으면 임시 코드마스터를 씁니다. |

`data` 폴더를 지우면 모든 분석 결과와 수정 기록이 삭제됩니다. 담보를 분석할 때에는 그 담보를 정의한 약관 구간의 텍스트와 별표 목록(표 이름과 쪽)이 Anthropic API로 전송됩니다. PDF 파일 자체, 다른 약관 구간, 별표 안의 수치, 분석 결과와 검토 기록은 전송하지 않고 이 PC에만 둡니다.

## 1단계 분석 방식

1단계는 AI를 쓰지 않고 정해진 규칙으로만 분석합니다. 그래서 같은 PDF는 항상 같은 결과가 나오며, 결과마다 근거가 되는 원문 위치가 붙습니다.

**쪽별 글자 추출**에서는 쪽마다 글자와 좌표를 읽습니다. 표의 열 사이처럼 넓게 벌어진 곳은 ` | `로 나눠 표시합니다. 글자가 거의 없고 이미지가 그려진 쪽은 스캔 쪽으로 판정합니다. 한 쪽이 왼쪽·오른쪽 두 단으로 편집된 약관은 쪽 가운데의 빈 세로 띠로 2단 편집을 알아보고, 왼쪽 단을 끝까지 읽은 뒤 오른쪽 단을 읽습니다.

**인쇄 쪽번호**는 쪽 위·아래 여백의 "12", "- 12 -", "12 / 340" 같은 숫자를 읽습니다. 표 안의 숫자를 쪽번호로 착각하지 않도록, 앞뒤 쪽과 번호 차이가 맞을 때만 인정합니다. 인정하지 못한 쪽은 "인쇄 쪽 미확인"으로 표시하고 추정하지 않습니다.

**머리글·바닥글 제거**에서는 쪽 맨 위·아래에서 같은 위치에 세 쪽 이상 반복되는 줄 가운데, 본문 문장 모양이 아니고 글자가 작거나 본문과 떨어져 있는 줄만 지웁니다. 조문 제목이나 본문 문장은 지우지 않습니다.

**조문 제목**은 `제3조(보험금의 지급사유)`, `제3조【보험금의 지급사유】`, `제3조[…]`, `제3조「…」`, `제3조의2(…)`, 괄호 없는 `제3조 보험금의 지급사유` 형식을 읽습니다. `제3조 제1항에 따라 …`처럼 조문 번호로 시작하는 본문 문장은 제목으로 보지 않습니다.

**구간 분리**에서는 "○○특약", "○○특별약관", "○○보통약관" 제목 줄(앞에 "1." 같은 번호가 붙어도 됨) 뒤에 제1조가 이어지는 곳, 그리고 제목이 없어도 조문 번호가 제1조로 다시 시작하는 곳을 약관 경계로 봅니다. "[별표 N]" 제목은 별표 구간으로 나눕니다. 목차가 있으면 목차의 약관·별표 항목과 본문 구간을 짝지어 빠진 약관이 없는지 확인합니다.

**목차 활용**: 목차가 있으면 목차의 약관 제목을 기준으로 본문 구간을 확인합니다. 본문 제목을 규칙만으로 알아보지 못한 특약은 (1) 본문에서 목차의 제목 글자를 찾아 그 줄에서 구간을 나누거나, (2) 제목 없이 제1조로 시작하는 구간의 시작 쪽이 목차의 쪽번호와 맞으면 목차의 제목을 붙입니다. 그래도 본문에서 찾지 못한 특약은 "목차 추정" 담보 후보로 트리에 올리고, 본문 근거가 없다는 점을 표시합니다. 이런 담보를 2단계에서 분석하려면 [편집]에서 정의 약관을 지정해야 합니다.

**담보 추출**에서는 각 약관의 "보험금의 지급사유", "보험금의 지급금액" 같은 조문에서 "○○보험금·○○진단비·○○수술비·○○입원급여금·○○입원일당·○○자금·○○연금" 형태의 이름을 찾습니다. 조문에 보험금명이 없고 "별표1 보험금 지급기준표"처럼 지급표를 참조하는 약관은 그 별표에서 보험금명을 찾습니다. 그래도 보험금명이 없는 약관(예: 보험료납입면제특약)은 약관 제목을 담보명으로 올려 빠뜨리지 않게 하고, 화면에 "확인 필요"로 알립니다.

**대분류**는 아래 순서로 정합니다. 앞의 규칙이 우선하며, 어떤 단서로 분류했는지 한 줄 근거를 남깁니다.

| 순서 | 판단 | 단서 |
|---|---|---|
| 1 | 담보명 | 사망 → 사망, 장해·장애 → 장해, 입원 → 입원, 수술·치료·통원·요양·간병·항암·방사선·약물 등 → 치료, 진단·발병 → 진단 |
| 2 | 지급사유 문장(담보명에 단서가 없을 때) | "사망하였을" → 사망, "장해지급률" → 장해, "입원하여" → 입원, "수술을 받" → 치료, "진단확정" → 진단 |
| 3 | 위 단서가 모두 없을 때 | 기타(예: 생활자금, 만기축하금, 응급실내원보험금) |

예를 들어 "암직접치료입원급여금"은 담보명에 "입원"이 있어 입원으로, "유족연금"은 담보명에 단서가 없지만 지급사유 문장의 "사망하였을"에 따라 사망으로 분류합니다. 장기요양간병자금처럼 분류가 갈릴 수 있는 담보는 [편집]으로 옮겨 주십시오.

### 담보가 이상하게 나올 때

담보가 0개이거나 엉뚱하게 나오면, 문서 요약 아래의 **[PDF 글자 확인]**을 펼쳐 조문이 시작하는 쪽 번호를 넣고 [보기]를 누릅니다. 앱이 그 쪽에서 읽은 글자가 줄 단위로 나오고, 흐린 줄은 머리글·쪽번호로 보고 뺀 줄입니다. 문서 요약의 "조문 제목 인식 n개"가 0이거나 매우 적으면 조문 제목 형식을 읽지 못한 것이므로, 조문 제목 줄이 어떤 모양으로 읽히는지 알려 주시면 규칙을 보완하겠습니다.

앱의 약관 읽기 규칙이 개선된 뒤 예전에 분석한 약관을 열면 자동으로 다시 분석합니다. 담보 이름 수정, 분류 이동, 선택, 검토 기록은 약관 제목과 자동 담보명이 같은 담보로 옮겨집니다.

### 알려진 한계

이 규칙은 생명보험 표준약관의 일반적인 문형("제N조(제목)", "1. …경우: ○○보험금", 표 형식 지급사유)을 기준으로 합니다. 담보명이 위 접미어(보험금·진단비 등)로 끝나지 않거나, 지급사유가 별도 표에만 있고 조문 안에 이름이 없으면 담보를 찾지 못할 수 있습니다. 실제 약관으로 처음 써 보신 뒤 빠지거나 잘못 잡힌 담보를 알려 주시면 규칙을 보완하겠습니다.

## 개발·검증

```bash
npm test                                                  # 자동 테스트(25건): 1단계(추출·2단 편집·목차 활용·구간·분류·트리·API·재분석), 2단계(코드마스터·원문 대조·응답 형식·분석 API)
NODE_PATH=$(npm root -g) npm run check:ui2 -- <저장폴더>   # 2단계 화면 점검(시험용 응답 사용, Claude API 호출 없음)
npm run build:codemaster                                  # codemaster/임시_코드마스터.xlsx 재생성
NODE_PATH=$(npm root -g) npm run build:sample             # 시험용 246쪽 더미 약관 PDF와 정답 파일 재생성(Playwright 필요)
NODE_PATH=$(npm root -g) node scripts/build-variant-pdf.js  # 2단 편집·【】 조문·지급기준표 별표 형식의 시험용 PDF 재생성
NODE_PATH=$(npm root -g) node scripts/build-toc-variant-pdf.js  # 본문 제목을 못 읽는 특약·목차에만 있는 특약을 담은 시험용 PDF 재생성
NODE_PATH=$(npm root -g) npm run check:ui -- <저장폴더>    # 실제 브라우저로 업로드·트리·편집·캐시 점검 후 화면 캡처
node scripts/build-artifact.js                            # 아티팩트판 페이지(build/artifact.html) 생성
NODE_PATH=$(npm root -g) node scripts/ui-check-artifact.js <저장폴더>   # 아티팩트판 점검(샘플 자동 분석, 전송 없음, 휴대폰 폭)
```

`samples/ai-fixtures/`에는 Claude 대신 쓰는 시험용 응답이 있습니다. `COVERAGE_AI_FAKE=samples/ai-fixtures npm start`로 실행하면 API 키 없이 "사망보험금" 담보의 분석 화면을 확인할 수 있습니다. 이 응답에는 원문에 없는 인용과 코드마스터에 없는 코드를 일부러 넣어, 근거 미확인·코드 확인 필요 표시가 제대로 나오는지 볼 수 있게 했습니다. 이 기능은 화면 흐름과 검증 로직만 확인하며, 실제 Claude 응답의 품질은 확인하지 않습니다.

`samples/sample_policy.pdf`는 표지·목차(쪽번호 없음), 보통약관과 특약 28개, 표 형식 지급사유, 별표 3개, 스캔 쪽 1개로 구성된 가상 약관입니다. `samples/sample_expected.json`은 생성기가 함께 만든 정답(구간 제목·시작 쪽, 담보명·대분류)이며, 테스트는 분석 결과를 이 정답과 대조합니다. 실제 약관은 저장소에 넣지 않습니다.
