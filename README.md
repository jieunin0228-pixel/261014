# ECS 룰 변환기

생명보험 약관(PDF·텍스트)과 담보를 넣으면 보험금 심사 시스템(ECS)의 룰 테이블 행을 만들어 엑셀로 내보내는 정적 웹앱입니다. 분석 방식은 두 가지입니다.

- **AI 분석**: Claude가 약관을 읽고 행을 제안하면, 코드가 각 행을 원문 인용과 코드표로 검증합니다. claude.ai 아티팩트에서 열었을 때만 동작하며, 보는 사람의 Claude 계정 사용량을 씁니다(API 키 불필요).
- **규칙 엔진(사망)**: 보통약관의 사망 급부만 정해진 문형 패턴으로 변환합니다. 더미 약관 검증용이며 로컬에서도 동작합니다.

## 사용 순서

1. [PDF·텍스트 열기]로 약관 PDF를 엽니다. 글자가 들어 있는 PDF여야 하며, 스캔 이미지 PDF는 글자 인식(OCR)을 거친 뒤 올려야 합니다.
2. 약관은 보통약관·특별약관·별표 구간으로 자동으로 나뉩니다. [담보]에 "전체" 또는 "수술비", "수술비, 암진단"처럼 입력하고 [대상 찾기]를 누르면 해당 구간과 그 구간이 인용하는 별표가 선택됩니다. 목록에서 직접 더하거나 뺄 수 있습니다.
3. [코드표 올리기]로 ECS 코드표 엑셀을 적용합니다. 양식은 [양식] 버튼으로 받습니다(시트: 청구사유·사고유형·사인그룹·급부·계약상태·변수). 올린 코드표는 보는 사람의 브라우저에만 저장됩니다.
4. [AI 분석]을 누르면 선택한 구간마다 Claude를 한 번씩 호출합니다(구간이 크면 조문 단위로 나눠 호출). [중지]로 멈출 수 있습니다.
5. 결과는 룰 테이블·심사자 수기·근거 없음 탭으로 나뉩니다. 행을 클릭하면 근거 원문과 주의·테스트 항목이 표시됩니다.
6. [엑셀 다운로드]로 룰테이블·심사자수기·근거없음·분석정보(정답지 비교를 했다면 정답지비교) 시트를 저장합니다.

## AI 결과 검증 방식

Claude의 응답은 그대로 쓰지 않고, 다음 검증을 통과한 행만 룰 테이블에 넣습니다.

| 검증 | 처리 |
|---|---|
| 인용문(quote)이 분석에 보낸 약관 원문에 글자 그대로 있는지(공백 무시) | 없는 인용은 근거에서 빼고 ⚠ 표시하며, 확인된 근거가 하나도 없으면 행을 만들지 않고 [근거 없음]으로 보냅니다(규칙 6). |
| 청구사유·사고유형·사인그룹·계약상태·급부 코드가 코드표에 있는지 | 없는 코드는 비우고 ⚠ 표시합니다. 코드가 비어 있으면 명칭이 정확히 같은 코드로 채웁니다. |
| 사인그룹 코드가 있는지 | 없으면 룰 행 대신 [심사자 수기]로 보냅니다(규칙 5). |
| 상세계산식 형식 | 괄호·허용 문자 규칙을 어기면 🔴 표시합니다. |
| 경계일·Math.max·코드표에 없는 변수 | 🔴 표시와 테스트 시나리오를 붙입니다(규칙 8). |
| 같은 청구사유·사고유형·사인그룹·조건에 급부가 둘 이상 | 🟡 표시합니다. |

이 검증은 "근거가 원문에 실제로 있는지"와 "코드가 코드표에 있는지"를 보장할 뿐이며, 산식 해석이 옳은지까지 보장하지는 않습니다. ECS 반영 전에는 심사자 확인과 정답지 비교가 필요합니다.

## claude.ai 아티팩트로 게시

`npm run build:artifact`로 `build/artifact.html`을 만들어 게시합니다. 함께 올리는 파일은 `src/*.js`, `samples/dummy-terms.js`, `samples/dummy-riders.js`, `samples/answer_key.json`, `vendor/cmaps-ko.js`이며, 선언하는 기능은 `sample`(Claude 호출)과 `downloads`(엑셀 저장)입니다. SheetJS·pdf.js는 게시본에서 jsDelivr의 같은 버전을 씁니다. 아티팩트에는 .xlsx 파일을 첨부할 수 없어서, [샘플 정답지로 비교] 버튼은 같은 내용의 `answer_key.json`을 읽습니다.

## 개발·검증

```bash
npm install
npm run build:vendor    # vendor/ 의 SheetJS·pdf.js·한글 문자표(cmaps-ko.js) 재생성
npm run build:samples   # samples/dummy_terms.txt, answer_key.xlsx, answer_key.json 재생성
npm test                # 단위 테스트(22건)
NODE_PATH=$(npm root -g) node scripts/build-sample-pdf.js   # samples/dummy_policy.pdf(다담보 샘플) 재생성
NODE_PATH=$(npm root -g) node scripts/ui-check.js /tmp      # 화면 점검(규칙 엔진·정답지 비교·엑셀)
NODE_PATH=$(npm root -g) node scripts/ui-ai-check.js /tmp   # AI 분석 흐름 점검(가짜 Claude 응답 사용)
```

`ui-ai-check.js`는 `test/fixtures/ai-surgery.json`을 Claude 응답 대신 돌려주므로, 화면 흐름과 검증 로직만 확인하며 실제 Claude 응답 품질은 확인하지 않습니다.

## 파일 구성

| 경로 | 역할 |
|---|---|
| `src/schema.js` | ECS 컬럼, 정답지 컬럼, 기본(더미) 코드 |
| `src/engine.js` | 규칙 엔진(사망), 위험 표시(🔴/🟡), 정답지 비교 |
| `src/ai.js` | 구간 분리·담보 선택, 코드표 읽기·양식, Claude 지시문, 결과 검증 |
| `src/pdf-text.js` | PDF 텍스트 추출(pdf.js, 한글 문자표 내장) |
| `src/app.js`, `index.html` | 화면 |
| `samples/dummy-terms.js`, `samples/dummy-riders.js` | 더미 보통약관, 더미 특별약관·별표 |

## 규칙 엔진(사망)의 입력 형식 전제

규칙 엔진은 생명보험 표준약관의 문언 패턴을 기준으로 한 규칙 기반 추출기이며, 약관을 자유롭게 이해하는 모델이 아닙니다. 다음 형식을 전제로 합니다.

- 조문은 `제N조(제목)`, 항은 `①②…`, 호는 `1.`, 목은 `가.` 형식이어야 합니다.
- 사망 급부는 제목에 "지급사유"가 들어간 조문의 호에서 `…사망하였을 경우: ○○보험금` 형식으로 읽습니다.
- 지급금액은 `가입금액의 N%`로, 감액은 `다만, … 계약일부터 N년 이내 … 가입금액의 N%`로 읽습니다.
- 면책은 제목에 "지급하지 않는 사유"가 들어간 조문에서 읽고, 사유는 `src/schema.js`의 사인그룹 키워드와 매칭합니다.

이 형식과 다른 문언은 행으로 만들어지지 않거나 "근거 없음"으로 분류되므로, 실제 약관에 적용하려면 패턴과 사인그룹 마스터를 확장해야 합니다.

## 변환 규칙 구현 내용

| 규칙 | 구현 |
|---|---|
| 1. 사고유형별 행 | 지급사유 문언의 원인 범위로 사고유형을 정합니다. 원인을 정하지 않은 "사망"은 일반·일반재해·교통재해, "재해로"는 일반재해·교통재해, "교통재해로"는 교통재해 행이 됩니다. |
| 2. 경과기간 감액 | 감액 단서는 `경과기간<=N년`(감액)과 `경과기간>N년`(정상) 두 행으로 나눕니다. 단서가 "재해 이외의 원인"으로 한정되면 일반 사고유형에만 적용합니다. |
| 3. 면책 | 사인그룹과 매칭되는 면책 사유는 `[가입금액] * 0` 행으로 만듭니다. "N년이 지난 후 … 재해 이외의 원인으로 사망한 경우에 해당하는 보험금" 예외는 기간 경계로 면책/지급 행을 나눕니다. |
| 4. 갱신형 | 갱신 조문이 있으면 최초·갱신 행을 나눕니다. 갱신 산식 조항이 명시한 급부에만 `Math.max([가입금액], [기납입보험료])`를 쓰고, 명시하지 않은 급부는 지급금액 조항 문언대로 두면서 ⚠를 표시합니다. |
| 5. 심사자 수기 | 사인그룹 마스터에 없는 사유(심신상실, 수익자·계약자 고의, 실종선고)는 룰 행 없이 [심사자 수기] 탭으로 보냅니다. |
| 6. 근거 조항 | 모든 행에 지급사유·지급금액·면책·소멸 조항과 원문 발췌를 붙입니다. 지급금액 조항을 찾지 못한 급부는 행을 만들지 않고 [근거 없음] 탭으로 보냅니다. |
| 7. ⚠ 표시 | 경계일 포함 여부, 면책기간 기산점, 갱신계약의 기산점 재설정, 갱신 산식 적용 범위, 면책 시 환급 여부, 소멸 조항의 급부 범위처럼 문언으로 확정할 수 없는 사항에 사유를 적습니다. |
| 8. 🔴/🟡 | 경계일 조건, Math.max 산식, 등록되지 않은 변수(`기납입보험료`, `보장개시경과기간`)는 🔴로, 동일 사고유형·사인그룹·조건에 급부가 둘 이상 매핑된 행은 🟡로 표시하고 테스트 시나리오를 적습니다. |

## 설계상 판단

- **구분 색상**: 사망보험금을 지급하는 행은 모두 계약이 소멸하므로, 소멸을 행 구분으로 쓰면 거의 모든 행이 파랑이 됩니다. 그래서 행 배경은 산식 결과(정상 초록, 감액 노랑, 면책 빨강)로 칠하고, 소멸(파랑)은 계약상태처리 열의 배지로 표시합니다.
- **정답지 매칭 키**: 구보장급부명, 사고유형, 사인그룹코드, 계산식결정조건 4개를 키로 짝을 짓고, 상세계산식과 계약상태처리를 비교합니다. 공백 차이는 무시합니다.
- **샘플 정답지의 의도된 차이**: 비교 기능을 시연하려고 2곳을 일부러 다르게 작성했습니다. 교통재해사망보험금의 갱신계약 산식(약관에 없는 Math.max 적용)과 사망보험금 × T20(전쟁) 행 2개입니다. 그래서 샘플 비교 결과는 일치 19, 불일치 1, 정답지에만 2입니다. 두 곳 모두 엔진이 ⚠로 확인을 요청한 지점입니다.

## 보안 참고

`xlsx` 0.18.5(npm 최종 배포판)에는 악의적으로 조작된 엑셀 파일을 읽을 때의 취약점 공지가 있습니다. 정답지 업로드에는 직접 만든 신뢰할 수 있는 파일만 사용해야 하며, 실데이터 환경으로 옮길 때에는 SheetJS 공식 배포처의 최신 버전으로 교체해야 합니다.
