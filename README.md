# 약관 변환·검증 앱 (1단계)

보험 약관 PDF를 조·항·호·목 단위의 구조화 데이터로 변환하고, 원본 PDF와 나란히 대조하며 검증·수정·승인하는 로컬 웹앱입니다. 신약관 출시 때 ECS 자동산출 룰을 입력하는 담당자에게 참고자료를 제공하기 위한 앱의 1단계이며, 2단계(담보 분류 트리) 이후는 1단계 검증이 끝난 뒤 만듭니다.

- **변환에는 AI를 쓰지 않습니다.** PyMuPDF로 글자 좌표를 읽고 정규식으로 분해합니다.
- **약관은 이 PC 밖으로 나가지 않습니다.** 서버는 `127.0.0.1`에서만 열리고, 결과는 `data/` 폴더에만 저장합니다. 이 폴더와 PDF 파일은 Git에 올라가지 않도록 `.gitignore`에 넣었습니다.

## 설치와 실행

Python 3.10 이상이 필요합니다(설치할 때 "Add python.exe to PATH"에 체크합니다).

**Windows:** `실행.bat`을 더블클릭합니다. 처음 한 번은 필요한 프로그램을 설치하고, 이후에는 바로 실행합니다.

**명령어로 실행:**

```bash
python -m pip install -r requirements.txt   # 처음 한 번
python run.py                                # 실행 → 브라우저가 http://127.0.0.1:8765 를 엽니다
```

끝낼 때는 실행 창에서 `Ctrl+C`를 누릅니다.

**스캔 PDF(OCR, 선택):** 글자가 없는 스캔 쪽을 읽으려면 Tesseract와 한국어 데이터를 설치합니다(Windows: UB Mannheim 배포판 설치 시 Korean 선택). 설치되어 있지 않으면 해당 쪽을 "OCR 필요(미설치)"로 표시하며, 외부 OCR 서비스로 보내지 않습니다.

## 사용 순서

1. **[PDF 올리기]**로 약관을 올립니다. 1,492쪽 약관 기준으로 약 1분 40초가 걸리며, 단계별 진행률이 표시됩니다. 같은 PDF를 다시 올리면 저장된 결과를 바로 엽니다.
2. **[대조 검증]** 탭에서 좌측 원본 쪽과 우측 추출 조각을 비교합니다.
   - 조각에 마우스를 올리면 원본에서 해당 줄이 노란색으로 강조됩니다.
   - ←/→ 키로 쪽을 넘길 수 있습니다.
   - 참조 칩(예: `제3조(보험금의 지급사유) → 제3조`)을 누르면 참조된 조문으로 이동합니다.
3. 잘못 나뉜 곳은 조각 아래 버튼으로 고칩니다. 모든 수정은 검토자 이름과 함께 **[수정·승인 이력]**에 남습니다.

   | 버튼 | 용도 |
   |---|---|
   | 글자 수정 | 추출 글자를 직접 고칩니다 |
   | 종류·번호·제목 | 조/항/호/목/별표/해설 종류와 번호를 바꿉니다(ID가 다시 계산됩니다) |
   | 나누기 | 선택한 줄부터 새 조각을 만듭니다(놓친 조문 제목 등) |
   | 앞 조각과 합치기 | 잘못 나뉜 조각을 앞 조각에 붙입니다 |
   | 첫 줄 ↑앞으로 / 끝 줄 ↓뒤로 | 조각 경계를 한 줄씩 옮깁니다 |

4. **[품질 보고서]**에서 경고를 하나씩 눌러 해당 쪽을 확인합니다. 경고 종류는 아래 표와 같습니다.
5. 대조를 마치면 검토자 이름을 넣고 **[변환 승인]**을 누릅니다. 승인한 뒤에 수정하면 승인이 자동으로 해제됩니다. 2단계 이후의 AI 해석은 승인된 변환 결과만 입력으로 받습니다.

## 품질 보고서 항목

| 항목 | 내용 |
|---|---|
| 텍스트가 거의 없는 쪽 | 글자가 20자 미만이거나, 이미지가 30% 이상인데 글자가 적은 쪽(스캔 의심) |
| 조문 번호 연속성 | 구간(주계약·특약)마다 제N조, 제2-N조 번호가 빠지거나 중복·역행한 곳 |
| 항·호·목 번호 끊김·중복 | ①②, 1.2., 가.나.가 1부터 차례로 이어지지 않는 곳 |
| 중복 ID | 같은 조문 ID가 두 번 나온 곳(번호 중복의 결과) |
| 참조 미해결 | "제○조", "제○항", "별표○", "앞 항", "다음 각 호"의 대상을 찾지 못한 곳 |
| 참조 미해결(해설 상자 안) | 【설명】·【예시】 상자 안의 법령 인용 등. 약관 본문 참조가 아니어서 따로 모읍니다 |
| 표 추출 불완전 | 표 영역 글자의 90% 미만만 추출되었거나 빈 칸이 75%를 넘는 표. 원본 이미지를 함께 저장합니다 |
| 표 재구성(원본 대조 권장) | 세로선이 없는 표를 머리줄 칸 위치와 가로선으로 다시 나눈 표. 원본 이미지를 함께 저장합니다 |
| OCR 저신뢰 구간 | OCR 신뢰도 70 미만인 줄이 있는 조각, OCR이 필요하지만 설치되지 않은 쪽 |

## 결과 파일 (`data/<PDF 해시>/`, [내려받기] 탭)

| 파일 | 내용 |
|---|---|
| `terms.json` | 구간 목록과 조각 목록(문서 순서). 조각마다 ID(`S006\|제7조-①-2`), 종류, 번호, 제목, 소속 경로, 시작·끝 쪽, 원문, 원본 좌표, 참조 연결(`refs`) |
| `tables.json` | 표의 행·열 JSON, 소속 조각, 추출 불완전·재구성 여부와 원본 이미지 경로 |
| `pages.json` | PDF 쪽 ↔ 인쇄 쪽번호 매핑, 쪽별 글자 수·이미지 비율·2단 여부·OCR 여부, 떼어 낸 머리글·바닥글 |
| `report.json` | 변환 품질 보고서 |
| `edits.json`, `status.json` | 수정 이력, 승인 상태와 이력 |

조문 ID는 `구간ID|조-항-호-목` 형식입니다. 특약마다 제2-1조가 반복되므로 구간 ID(S001…)를 앞에 붙입니다. 해설 상자는 `-해설N`, 별표는 `별표2-1`로 표시합니다.

## 변환 방식

1. **줄 복원:** 글자 좌표로 줄을 다시 만듭니다. 띄어쓰기 공백 문자가 없는 PDF도 글자 사이 간격(글자 크기의 20% 초과)으로 띄어쓰기를 복원합니다. 가운데를 가로지르는 줄이 거의 없고 좌우에 줄이 고루 있는 쪽은 2단으로 보고, 왼쪽 단 → 오른쪽 단 순서로 읽습니다.
2. **머리글·바닥글:** 쪽 위아래 7.5% 띠 안에서 숫자만 있는 줄은 인쇄 쪽번호로 기록하고, 3쪽 이상 반복되는 문구는 머리글·바닥글로 떼어 냅니다.
3. **구간:** PDF 북마크가 있으면 그것을, 없으면 책 앞쪽 목차 쪽을 읽어 주계약·특약 구간을 나눕니다. 목차에 빠진 특약은 쪽 첫 줄의 큰 글씨 "○○ 약관" 제목으로 찾습니다. 색인·약관요약서·인용조문 같은 부속 자료는 조문으로 나누지 않고 쪽 단위 원문으로 둡니다.
4. **조문 분해:** `제N조【제목】`(또는 제목만 있는 `제N조(제목)`) 줄, `제N편·관·절`, `①`, `1.`, `가.`, `별표N` 줄로 나눕니다. 다음 두 경우는 잘못 나누지 않도록 제외합니다.
   - 조문 제목보다 깊이 들여 쓴 `①`은 예시 속 인용으로 보고 항으로 나누지 않습니다.
   - `…합니\n다. 다만`처럼 줄바꿈으로 생긴 `다.`도 앞 번호가 없으면 목으로 보지 않습니다.
5. **해설 상자:** 테두리 상자 안의 【설명】·【예시】 등은 본문 조문과 섞이지 않게 `해설` 조각으로 따로 둡니다.
6. **표:** 선이 그려진 표를 행·열 JSON으로 저장하고, 본문에는 `[표 T0001]` 자리 표시만 남깁니다. 표를 문장으로 풀어 쓰지 않습니다.

## 샘플 약관 점검 결과

대상 파일은 `(무)하나로 라이트 3.10.5 간편건강보험(갱신형)_계약자용약관(2607).pdf`(1,492쪽)입니다.

| 점검 항목 | 결과 |
|---|---|
| 텍스트형·스캔형 | 텍스트형입니다. 글자가 없는 쪽은 2쪽(빈 쪽) 하나뿐입니다. 본문 821쪽은 공백 문자 없이 글자 간격으로만 띄어 쓰여 있어 간격 기반 복원이 필요했습니다 |
| 단 구성 | 본문은 1단입니다. 약관요약서(21~44쪽)는 표 형식이라 2단처럼 보이며, 부속 자료로 분류해 조문 분해에서 뺐습니다 |
| 목차·북마크 | 북마크는 없습니다. 7~10쪽 목차에 115개 항목(부속 자료·주계약·특약 일반사항·특약 103개 등)과 시작 쪽이 있고(`0335 R(무)3대주요암진단특약…`), 주계약(45~46쪽)과 특약 일반사항(79~80쪽)은 구간마다 조문 목차가 따로 있습니다. 목차에 없는 특약 2개는 본문 제목으로 찾았습니다 |
| 조·항·호 표기 | `제N조【제목】`(주계약), `제1-N조`(특약 일반사항), `제2-N조`, `제2-N조의M`(각 특약), `제N편`·`제N관`, `①`, `1.`, `가.`, `1)`·`가)`(세목, 조각으로 나누지 않음)입니다. 특약은 "제1편 일반사항은 특약 일반사항 제1-1조~제1-17조를 따른다"는 방식으로 공통 조문을 참조합니다 |
| 별표 | 특약마다 `별표2-1 보험금 지급기준표`, 분류표(암·뇌혈관질환 등), 의약품명 표, 적립이율 표가 있습니다. 467개 표 중 66개는 세로선이 없어 재구성했고, 3개는 빈 칸이 많아 불완전으로 표시했습니다. 장해분류표(96~120쪽)는 문장과 표가 섞여 있으며, 여러 쪽에 걸친 표는 쪽마다 따로 저장됩니다 |
| 머리글·바닥글 | 위쪽에 상품명 또는 특약명, 아래쪽에 쪽번호가 있습니다 |
| PDF 쪽과 인쇄 쪽번호 | 표지(1쪽)를 빼면 모든 쪽에서 같습니다 |

변환 결과는 구간 116개, 조 2,162개, 항 4,369개, 호 1,399개, 목 427개, 별표 340개, 해설 상자 1,202개, 표 467개, 참조 5,925건입니다. 이 중 남은 경고는 다음과 같습니다.

- **번호 중복:** 411쪽 제2-3조와 1279쪽 제2-3조는 PDF 원문 자체에 항 번호가 중복 인쇄되어 있습니다.
- **참조 미해결:** 27건입니다.
- **표 재구성:** 66건이며, 원본 대조가 필요합니다.

## 개발·검증

```bash
python tests/make_fixture.py          # 시험용 합성 약관 PDF 재생성(tests/fixtures/sample_terms.pdf)
python -m unittest discover tests     # 자동 테스트
NODE_PATH=$(npm root -g) node scripts/ui_check.js <저장폴더>   # 화면 점검(서버 실행 중, Playwright 필요)
```

| 경로 | 역할 |
|---|---|
| `termsapp/extract.py` | 쪽 단위 추출: 줄·띄어쓰기 복원, 2단, 머리글·바닥글, 표·상자, OCR |
| `termsapp/structure.py` | 목차·구간, 조·항·호·목·별표·해설 분해, ID·경로, 계층 재계산 |
| `termsapp/refs.py` | 참조 표현 찾기와 대상 연결 |
| `termsapp/quality.py` | 변환 품질 보고서 |
| `termsapp/pipeline.py` | 변환 흐름, 결과 저장과 캐시 |
| `termsapp/store.py` | 수정·이력·승인 |
| `termsapp/server.py`, `termsapp/static/` | 로컬 서버와 검증 화면 |
| `legacy/` | 이전 버전(브라우저 단독 ECS 룰 변환기). 참고용으로 보존하며 실행 경로에서 쓰지 않습니다 |
