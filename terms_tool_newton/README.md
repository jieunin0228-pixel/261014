# 약관 구조화 도구 (1~5단계)

보험 약관 PDF를 담보(특약)별·조문별 구조화 데이터로 바꾸고, 담당자가 원본 쪽과 나란히 대조하여 검증·수정·승인하는 로컬 웹앱입니다. 신약관 출시 시 ECS 자동산출 룰을 입력하는 담당자의 참고자료를 만드는 1단계이며, ECS와 연동하지 않습니다.

- 1단계 변환은 AI를 쓰지 않고 PDF 라이브러리(PyMuPDF)로만 처리합니다.
- 약관과 결과는 이 PC의 `data/` 폴더에만 저장되며, 1단계는 외부로 아무것도 보내지 않습니다.
- 화면은 이 PC에서만 열립니다(127.0.0.1). 같은 사내망의 다른 PC에서는 접속할 수 없습니다.
- 2단계 이후(분류·결과 카드·ECS 초안·구약관 비교)는 1단계에서 [변환 승인]한 문서에만 실행됩니다.
- 3·4단계는 Claude API를 쓰며, API 키가 없으면 실행 단추가 잠깁니다(1·2·5단계는 키 없이 동작).
- 이 폴더(`terms_tool_newton`)는 다른 작업 세션의 결과물과 섞이지 않도록 따로 둔 폴더입니다.

## 설치와 실행

### Windows (권장 방법: 두 번 클릭)

1. Python 3.10 이상을 설치합니다(https://www.python.org/downloads/ , 설치 첫 화면에서 **Add python.exe to PATH**를 체크).
2. 이 폴더(`terms_tool_newton`)의 **`run_windows.bat`** 을 두 번 클릭합니다.
   - 처음 한 번은 필요한 프로그램을 내려받아 설치하므로 몇 분 걸립니다(인터넷 연결 필요). 두 번째부터는 바로 시작합니다.
   - 브라우저가 자동으로 열리지 않으면 주소창에 `http://127.0.0.1:8765` 를 입력합니다.
3. 끝낼 때는 검은 창을 닫거나 그 창에서 `Ctrl + C`를 누릅니다.

### 명령어 두 줄로 실행 (Windows·Mac·Linux 공통)

```bash
pip install -r requirements.txt
python app.py
```

Mac·Linux에서는 `./run.sh` 로도 실행할 수 있습니다. 회사 PC에서 `pip install`이 프록시 때문에 실패하면 전산 담당자에게 사내 PyPI 미러 또는 프록시 설정을 요청합니다.

### 스캔(이미지) PDF용 OCR (선택)

글자가 들어 있는 PDF(텍스트형)는 OCR이 필요 없습니다. 스캔형 쪽이 있을 때만 로컬 OCR(Tesseract, 한국어)을 씁니다. 설치되어 있지 않으면 해당 쪽을 품질 보고서에 "OCR 미실행"으로 표시하고 넘어갑니다.

- Windows: Tesseract 설치 프로그램(UB Mannheim 배포판)으로 설치하면서 언어 목록에서 **Korean**을 선택하고, 설치 폴더(예: `C:\Program Files\Tesseract-OCR`)를 PATH에 추가합니다.
- Mac: `brew install tesseract tesseract-lang` / Ubuntu: `sudo apt install tesseract-ocr tesseract-ocr-kor`

## 사용 순서

1. **문서 탭**: [파일 선택]으로 약관 PDF를 고르고 [변환 시작]을 누릅니다. 진행률(텍스트·표 추출 → 목차·머리글 대조 → 조문 구조화 → 참조 연결)이 표시됩니다. 1,492쪽 샘플 기준 약 40초 걸립니다. 같은 PDF를 다시 올리면 이전 결과(캐시)를 바로 엽니다.
2. **품질 보고서 탭**: 변환 결과의 문제 항목을 한 화면에서 확인합니다. 쪽번호·담보 ID를 누르면 검증 화면의 해당 쪽·담보로 이동합니다. 아래쪽 **담보별 요약표**는 엑셀·JSON으로 내려받을 수 있으며, 체크한 담보만 내보낼 수도 있습니다.
3. **검증 탭**: 왼쪽에서 담보를 고르면 가운데에 원본 PDF 쪽(그 담보의 시작 쪽), 오른쪽에 추출한 조문 트리가 나옵니다.
   - 조문을 누르면 원본 쪽으로 이동하고 그 조문의 줄을 노란색으로 표시합니다. 다시 누르면 추출 본문을 펼칩니다.
   - 파란 점선은 추출한 표, 빨간 점선은 "표 추출 불완전" 표, 초록 점선은 설명 상자(【유의사항】 등)입니다.
   - [표] 탭은 추출한 표를 행·열 그대로 보여 줍니다(병합 칸 포함, 문장으로 풀어 쓰지 않음).
   - [참조] 탭은 본문 속 "제○조", "별표○", 「법령」, "제1편 일반사항", "주계약 약관의 준용" 표현과 연결 대상을 보여 줍니다. 연결하지 못한 참조는 "참조 미해결"로 표시합니다.
   - [분석 입력 구성] 탭은 2단계 이후 AI에 이 담보에 대해 전달할 범위(담보 구간 전체, 참조하는 특약 공통 조문, 준용하는 보통약관 조문, 참조 별표·인용조문)를 보여 줍니다.
4. **수정**: 잘못된 부분은 직접 고칩니다. 모든 수정은 이력으로 저장되며 [문서] 탭의 수정 이력에서 하나씩 되돌릴 수 있습니다.
   - 담보 유형: 오른쪽 위 [담보 유형] 선택상자
   - 담보 쪽 범위: [쪽 범위] 입력 후 [범위 저장]
   - 조문 경계: [조문 경계 수정]을 켜면 원본 쪽의 줄을 눌러 "이 줄에서 새 조문(또는 별표) 시작"을 지정하거나, 조문 제목줄의 [번호·제목]·[앞 조문에 합치기]를 쓸 수 있습니다.
5. **검토 상태**: 담보마다 [검토완료로 표시]를 누릅니다. 검토완료 후 그 담보를 수정하면 자동으로 "미검토"로 돌아갑니다.
6. **변환 승인**: 화면 오른쪽 위 상태 표시(변환 미승인)를 누르면 미검토 담보 수와 남은 문제 수를 확인한 뒤 승인할 수 있습니다. 승인 후 수정이 생기면 승인은 자동으로 해제됩니다. 2단계 이후의 AI 해석은 승인된 문서에만 실행되도록 만들 예정입니다.

화면 오른쪽 위 [작업자]에 이름을 넣어 두면 수정·검토·승인 이력에 기록됩니다.

## 2단계: 담보 분류 트리

[담보 분류] 탭에서 사용합니다. 1단계 [변환 승인]이 되어 있어야 실행되며, 승인이 풀리면 실행 단추가 잠기고 경고를 표시합니다.

1. **[자동 구성(규칙·기억)]**: 보통약관·개별특약·납입면제류·서비스·인수·전환류(·미분류) 담보를 대분류(사망·장해·진단·입원·치료·기타 고정) → 중분류(질환군: 암, 뇌혈관, 심장, 뇌·심장, 재해, 질병, 특정질병, 질병·재해 공통, 납입면제 등) → 소분류(보장 형태: 수술, 로봇수술, 방사선치료, 약물치료, 통원, 검사, 상급종합병원, 일반암 등)로 나눕니다.
   - 담보명 낱말로 정하고, 담보명으로 정할 수 없으면 지급사유 조문의 표현(사망·장해·진단확정·입원·수술)으로 정하며 그 문장을 근거 인용으로 남깁니다.
   - 어디에도 맞지 않으면 '기타'에 넣고 분류 근거를 한 줄로 남깁니다.
   - 이전 약관에서 사람이 옮기거나 검토완료한 분류는 `data/_memory/classification_memory.json`에 기억되며, 같은 담보(상품 꼬리표를 뗀 담보명 기준)에는 기억을 먼저 적용합니다.
   - 사용자가 옮긴 분류는 다시 [자동 구성]을 눌러도 유지됩니다. [처음부터 다시 구성]은 이 문서의 사용자 분류를 버립니다(기억은 남음).
2. **체크박스**: 3단계 이후 분석할 담보를 고릅니다. 상위 분류를 체크하면 하위 담보가 모두 선택되고, 일부만 선택되면 상위는 부분 선택으로 표시됩니다. 선택은 저장됩니다.
3. **[분류 옮기기]·[표시 이름]·그룹 [이름 변경]**: 담보를 다른 분류로 옮기거나 이름을 고칩니다. 바꾼 내용은 기억에 저장되어 다음 약관에서도 참고합니다.
4. **[검토완료]**: 분류를 사람이 확인한 담보를 표시합니다(원칙 5). 검토완료한 분류도 기억에 저장됩니다.
5. **[AI 분류 제안]**(선택): 담보명·지급사유 조문·지급기준표 급부명만 Claude API로 보내 분류를 제안받습니다(약관 PDF 전체는 보내지 않음). 제안마다 근거 조문 ID와 원문 인용을 받아, 인용이 그 조문 원문에 실제로 있는지 공백을 무시하고 문자열로 대조합니다. 맞지 않으면 "근거 불일치"로 표시하고 적용할 수 없게 합니다. 제안은 [적용]을 눌러야 반영됩니다.
6. 엑셀 내보내기에 '담보분류' 시트가, JSON 내보내기에 `classification.json`이 들어갑니다.

### AI 사용 설정

AI 기능(2단계 AI 분류 제안, 3·4단계)을 쓰려면 Anthropic API 키를 **서버를 실행하는 창의 환경변수**로만 넣습니다(화면이나 파일에 저장하지 않음).

- Windows: 명령 프롬프트에서 `set ANTHROPIC_API_KEY=sk-ant-...` 를 입력한 뒤 같은 창에서 `run_windows.bat`(또는 `python app.py`)를 실행합니다. 계속 쓰려면 [시스템 속성 → 환경 변수]에 사용자 변수로 등록합니다.
- Mac·Linux: `export ANTHROPIC_API_KEY=sk-ant-...` 후 `./run.sh`
- 모델은 기본 `claude-opus-5-5`이며 `TERMS_AI_MODEL` 환경변수로 바꿀 수 있습니다. 거절(refusal) 시 서버 측 대체 모델(`fallbacks: "default"`)을 쓰도록 설정되어 있습니다.

## 3단계: 담보별 결과 카드

[결과 카드·ECS 초안] 탭에서 담보를 체크하고 [결과 카드 만들기]를 누릅니다(왼쪽 목록은 기본으로 2단계에서 선택한 담보만 보여 줍니다).

- AI에는 담보 하나씩, 매칭 규칙 6번의 입력(담보 구간 전체, 참조하는 특약 공통 조항 — 공통 전체 적용이면 공통 조문 전부, 참조하는 보통약관 조문, 참조 별표·인용조문과 표)만 보냅니다. PDF 전체는 보내지 않습니다. 특약 공통 조항은 프롬프트 캐시로 재사용합니다.
- 입력의 조문·표마다 참조 번호(N·C·M·X·L·T)를 붙여 보내고, AI는 정해진 JSON 스키마로 답합니다. 모든 항목에 근거(참조 번호 + 원문 인용 한두 문장)가 있어야 합니다.
- 프로그램이 인용문이 해당 조문 원문에 실제로 있는지 공백을 무시하고 대조합니다. 맞지 않으면 "근거 불일치"로 표시하고 결과에서 빼서 [근거 불일치로 격리한 항목]에만 보여 줍니다.
- A. 보장 세부조건: 지급사유, 지급금액과 산식, 지급횟수와 한도, 보장개시일, 면책기간, 감액기간과 감액비율, 보험기간과 갱신 여부, 지급하지 않는 사유, 요건의 세부 정의, 지급 후 처리. 근거를 찾지 못한 항목은 "약관에 명시 없음"입니다.
- B. 전산화 시 주의사항: 별표 참조, 산출에 영향을 주는 용어 정의, 단서·예외 분기, 중복지급·택일, 경과기간·연령·성별별 지급률, 기준일 판단. 해석이 갈리면 "해석 확인 필요"와 가능한 해석을 함께 적습니다.
- C. 근거: 조·항·호와 쪽, 원문 인용을 표시합니다. 근거를 누르면 [검증] 화면에서 원본 쪽으로 이동하고 인용 문장이 걸친 줄을 주황색으로 강조합니다.
- 별표의 수치·지급률은 풀어 쓰지 않고 1단계에서 추출한 표를 그대로 보여 줍니다.
- 항목마다 검토 상태(미검토/검토완료)를 저장합니다.

## 4단계: ECS 룰 입력 초안

같은 탭의 [ECS 룰 입력 초안(4단계)]에서 봅니다. 결과 카드를 먼저 만든 뒤 [ECS 초안 만들기](또는 [둘 다])를 누릅니다.

- ECS "약관분석 데이터 관리" 화면과 같은 필드 순서·이름(상품·청구 / 계산식 / 상세계산식·처리)으로, 필드마다 "수정 전 / 수정 후" 칸과 근거 링크, 검토 상태를 둡니다. 단일 약관이면 "수정 후"만 채우고, 5단계 비교를 했으면 구약관 초안 값을 "수정 전"에 채웁니다.
- 상품코드·상품명·판매개시일자는 위쪽 [상품 정보]에 직접 입력합니다(약관에서 읽지 않음).
- 코드와 명칭은 쌍으로 다룹니다. **코드마스터 엑셀을 올리면 그 안의 코드만 제안**하고, 없으면 코드는 비우고 명칭만 적은 뒤 "코드 확인 필요"로 표시합니다. 양식은 [양식 내려받기]로 받습니다(열: 필드명·코드·명칭). 코드마스터는 이 PC에 저장되어 모든 문서에 적용됩니다.
- 조건 분기로 행이 나뉘어야 하면 행을 나누어 제안하고 근거를 적습니다. 행 분리 기준은 제공된 ECS 화면 예시(청구사유 × 사고유형, 급부결정조건)를 따릅니다.
- 약관에서 판단할 수 없는 필드는 "약관에 명시 없음" 또는 "사용자 입력 필요"로 표시합니다. 근거 인용이 맞지 않는 값은 칸을 비우고 "근거 불일치로 비운 칸"에 따로 보여 줍니다.
- [수정] 단추로 담당자가 값을 고칠 수 있으며 "사용자 수정"으로 표시되고 이력에 남습니다.

## 5단계: 구약관 대비 비교

1. 구약관 PDF를 [문서] 탭에서 올려 1단계 변환·검증·[변환 승인]을 합니다(신약관과 같은 절차).
2. 신약관을 연 상태에서 [구약관 비교] 탭의 '비교 기준'에서 구약관을 고르고 [비교 실행]을 누릅니다.
- 담보 짝은 담보명 유사도(상품 꼬리표·버전 번호 제외)와 목차상 위치로 자동 제안하며, 표의 선택상자로 바꿀 수 있습니다. 짝이 없으면 신규/삭제로 표시합니다. 변경구분은 신규·변경·삭제·동일이고 [변경된 담보만 보기]로 거를 수 있습니다.
- [상세]에서 조문·별표별로 구 원문과 신 원문을 나란히 보여 주고 바뀐 부분을 빨강(빠짐)·초록(더함)으로 표시합니다. 양쪽 쪽번호를 누르면 원본을 엽니다.
- 의미 변경 여부는 확정하지 않고, 바뀐 부분에 숫자·기간·%·단서·제외 표현이 있으면 "의미 변경 가능성 높음", 아니면 "표현 변경으로 보임" 의견만 붙입니다(AI 미사용).
- 변경 건마다 "ECS 룰 수정 필요 필드"를 붙입니다. 양쪽에 4단계 초안이 있으면 필드별 실제 차이로, 없으면 바뀐 조문의 종류(지급사유·세부규정·면책·지급기준표 등)로 추정합니다.
- [엑셀(수정 전/수정 후)]은 비교요약, 조문변경, ECS 수정전후(필드별 수정 전·수정 후) 시트를 내려받습니다.

## 변환 규칙 (매칭 규칙 구현 내용)

| 순서 | 내용 | 감지 실패 시 |
|---|---|---|
| 1 | 앞쪽 80쪽 안에서 "쪽번호(3~4자리) + 담보명" 줄이 5개 이상인 쪽(또는 "목차"라는 글자가 있고 2개 이상인 쪽)의 첫 연속 구간을 목차로 봅니다. 꼬리글의 인쇄 쪽번호와 PDF 쪽번호의 차이(최빈값)를 오프셋으로 계산합니다. | 보고서에 "목차를 찾지 못함"을 표시합니다. |
| 2 | 쪽 상단 7% 안의 작은 글씨(10.6pt 이하)를 머리글로 보고, 공백을 지운 뒤 목차 담보명과 대조합니다(완전 일치, 없으면 유사도 0.9 이상). | "목차에 없는 머리글"로 보고합니다. |
| 3 | 담보 범위는 목차 시작 쪽 ~ 다음 항목 시작 쪽 직전입니다. 쪽 배정은 사용자 수정 > 머리글 > 목차 범위 순으로 정하고, 머리글과 목차 범위가 다른 쪽을 불일치 목록으로 만듭니다. | 불일치·미배정·쪽 끊김을 보고합니다. |
| 4 | 담보 안에서 `제N조【제목】`, `제N-N조(의N)【제목】`, `별표N(-N) 제목`(쪽 첫 줄 부근), `제N편`·`제N관`을 찾고, 항(①), 호(1.), 목(가.), 세목((1))을 부모 조문에 붙여 `담보명/제2-2조/②/3` 형식의 ID를 줍니다. 항·호·목 번호는 1부터 차례로 이어질 때만 새 단위로 인정합니다. 조문 머리의 왼쪽 위치는 담보별로 계산합니다. | 번호 끊김·역전·중복을 보고합니다. |
| 5 | 담보 유형: 보통약관, 특약공통, 개별특약(지급사유 조문), 납입면제류(납입면제사유 조문), 서비스·인수·전환류, 인용조문, 부속자료(색인·가이드북·요약서), 미분류. 핵심 조문(지급사유, 세부규정, 면책, 지급기준표)을 지정합니다. | "지급사유 조문 없는 담보"로 보고합니다. |
| 6 | 참조 연결: `제1-N조`→특약공통, `제2-N조`→같은 특약, 번호 체계가 다른 `제N조`→문맥에 "주계약"이 있을 때만 보통약관, 「법령」/"○○법 제N조"→인용조문, `별표1-N`→특약공통, `별표2-N`→같은 특약, "제1편 일반사항"→특약공통 전체, "주계약 약관의 준용"→보통약관 전체. | "참조 미해결"로 목록화하고 사유를 적습니다. |
| 7 | 표는 쪽의 벡터 그림(진한 가는 가로 띠=행 구분, 흰 세로 여백·세로 괘선=열 구분)으로 격자를 복원해 행·열 JSON으로 저장합니다. 설명 상자(【…】)는 표에서 뺍니다. 표가 다음 쪽으로 이어지면 앞뒤 표를 연결합니다. | 병합 칸이 직사각형이 아니거나 칸에 배정되지 않은 글자가 있으면 "표 추출 불완전"으로 표시하고 쪽 이미지를 저장합니다. |
| 8 | 결과 파일을 `data/<문서ID>/`에 저장하고, 같은 PDF(SHA-256 동일)는 캐시를 씁니다. | — |
| 9 | 글자가 거의 없고 이미지가 쪽의 절반 이상인 쪽은 스캔형으로 보고 로컬 OCR(한국어)을 적용합니다. 줄별 신뢰도 70 미만을 저신뢰로 표시합니다. | OCR 미설치·저신뢰 구간을 보고합니다. |

추가로, 일부 쪽은 PDF 텍스트 층에 띄어쓰기 문자가 없고 글자 간격으로만 띄어 쓰여 있어(예: "이특약에있어서"), 글자 사이 간격이 글자 크기의 18%를 넘으면 띄어쓰기로 복원합니다. 2단계의 인용문 대조는 공백을 무시하고 비교할 예정이므로 이 복원이 대조 결과를 바꾸지 않습니다.

## 시험

```bash
python -m unittest discover -s tests -t . -v
# 샘플 약관 회귀 시험(약 40초)
SAMPLE_PDF="../(무)하나로 라이트 3.10.5 간편건강보험(갱신형)_계약자용약관(2607).pdf" python -m unittest discover -s tests -t .
```

`tests/test_stage345.py`는 분석 입력 구성(규칙 6), 결과 카드의 인용 대조·격리·약관에 명시 없음, ECS 초안의 코드마스터 유무 처리·근거 불일치 비움·사용자 수정, 승인 확인, 구약관 비교(짝·변경 표시·짝 바꾸기·엑셀), 근거 문장 위치 찾기를 가짜 AI 응답으로 시험합니다. `tests/test_stage2.py`는 분류 구성, 승인 확인, 옮기기·이름 변경·기억, 선택·검토, AI 제안의 인용 대조(가짜 응답 사용)를 시험합니다. 실제 Claude 응답 품질은 시험하지 않습니다.

`tests/make_fixture.py`가 만드는 10쪽짜리 시험용 PDF(목차, 머리글 불일치 쪽, 표, 참조, 스캔 쪽 포함)로 목차·오프셋, 불일치 보고, 조문 ID, 유형, 참조 연결, 표 격자, OCR, 수정·되돌리기·승인 자동 해제, 내보내기, 캐시를 시험합니다.
